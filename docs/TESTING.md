# Проверки

Из каталога проекта: `npm run typecheck`, `npm run lint`, `npm test`, `npm run build`. Осмысленные доменные тесты: порог 4/5 и удаление пятой записи, ровно три вопроса, пропуски, ручные теги и старый текст, актуальность основания, удалённые источники, идемпотентность, атомарный пакет.

E2E: CRUD профилей/записей, архив/возврат, фильтры и полный поиск, источники, A/B, настройки, экспорт, очистка, демо-изоляция, прямые URL, назад и перезагрузка, чтение в другом браузере. A должен обновлять единые Сигналы; пакеты A/B видны как события Журнала. Новых дописок нет, исторические доступны. Проверять ожидания от партнёра, автоматическое пополнение контекста, его правку/удаление и актуальность для следующего запроса. Ошибки БД/AI/timeout/квоты симулируются в тестовом окружении. Облачные интеграционные тесты только на выделенном вымышленном наборе.

Визуальная QA: 390×844, 1440×900, 360px; обзор, профиль, лента, запись, сигналы, три вопроса, ответ, меню, sheet и длинный текст. Проверять touch targets, фокус, safe-area, reduced-motion, FAB и стабильную AI-шапку. Эмуляция viewport не считается проверкой реальной мобильной клавиатуры.

Оценка настоящей модели по историям §14 ТЗ отдельно от mock: отсутствие выдуманного позитива и мотивов; один эпизод дважды; пропуски; разные ответы B; prompt injection; неизвестные источники; конкурентная ручная правка. Не запускать реальные вызовы на каждый build.

Результаты с датой и доказательствами — TEST_REPORT; R01–R22 — REQUIREMENTS_CHECKLIST. «Пройдено» только после фактической проверки; код интеграции без аккаунта не подтверждает облако.

Production smoke: SMOKE_API_BASE задаёт адрес Netlify; SMOKE_ONLY_B=1 проверяет B отдельно после уже пройденного A, SMOKE_ONLY_A=1 — A и контекст без повторения B. Каждый запуск создаёт и удаляет только собственный вымышленный набор. Проверка серверной очереди не использует браузер: нейтральная запись должна получить завершённую пустую разметку. Busy повторяется до пяти попыток, включая статус background worker; сетевые ошибки модели автоматически не повторяются. CAS-сравнение должно игнорировать порядок строк PostgreSQL и автоматические теги, сохраняя защиту от настоящей конкурентной правки.
