# Контракт AI

Серверный провайдер: GigaChat-2-Max; доступ подтверждён реальными запросами в рамках Freemium. Промпты версионируются, ответы проходят Zod-схему и проверку цитат. Модель видит только выбранного человека, текущие записи/теги, обе стороны контекста и релевантные ответы. Пользовательский текст трактуется как данные, не команды.

Операции: tags, signals, questions A/B, submit A/B, amendment. Порог >=5 действует на все аналитические операции, включая незавершённые разборы; tags — исключение. Выключенное согласие блокирует запросы на сервере и применение запоздалого результата. Идеи не вызывают модель.

Нормально один проход генерации на операцию; максимум один исключительный повтор при невалидной схеме или источниках с безопасным описанием ошибки. Сетевую ошибку провайдера автоматически не повторять. Три вопроса — три отдельных вопроса с темами; повторённый конечный знак вопроса нормализуется, несколько самостоятельных вопросов отклоняются. Пропуск `-`/`—` хранится как skipped и не становится фактом. Все пропуски A: сохранить пакет без модели, AI-lock и дополнений. Содержательный A обновляет единые Сигналы, исходные ответы остаются отдельным событием Журнала.

Модель выбирает готовые фрагменты sources по короткому ref, без UUID и самостоятельного текста цитаты. Серверный реестр строится только из разрешённых источников выбранного человека; фрагменты сохраняют точную подстроку исходного текста. Сервер заменяет ref на ID, цитату и подпись и повторно выполняет каноническую проверку. Неизвестный ref, посторонние поля цитаты и неподтверждённое повторение отклоняются. Дополнения используют sourceRef ответа/дописки. Текущий пакет содержательных ответов и новая дописка должны присутствовать в источниках результата. Сохраняемый формат результатов не изменился. Паттерн требует два разных эпизода из разных записей, а не два описания одного события. Значимые выводы имеют источники; гипотезы обозначаются и не получают вероятностей. Контекст/ответы тоже допустимые источники, с понятным переходом.

Нет диагнозов, ярлыков, рейтингов, директив уйти/остаться и выдуманного позитива. Отсутствие записи не доказывает отсутствие разговора/мотива. Сводки не становятся новыми фактами. B должен заметно учитывать содержательные ответы, показывать неизвестное и один следующий наблюдаемый шаг. Качество смысла проверяется отдельными историями, валидная цитата сама по себе не доказывает вывод.

Лимиты длины, timeout, сериализация и серверный rate limit защищают квоту. Переполнение контекста не обрезает журнал молча: показывается ошибка ограничения. Квота/недоступность AI не ломают CRUD. Реальные проверки модели и mock-тесты описываются раздельно.


Текущая модель аналитики — GigaChat-2-Max (бесплатная квота). Для tags применяется response_format json_schema, для аналитики — JSON-промпт и локальная строгая проверка: сложная схема провайдера воспроизводимо превышала 20-секундный timeout. Pattern консервативно требует минимум две разные даты события. Это не гарантирует смысловой истинности вывода; модельные оценки фиксируются отдельно. [Форматы Sber](https://developers.sber.ru/docs/ru/gigachat/guides/structured-output).

Production AI работает в фоновой задаче. Внутренний анализ ограничен 110 секундами, worker 240 секундами; OAuth до 8 секунд, генерация до 60 секунд, резерв 12 секунд на фиксацию. Единственный повтор валидации использует оставшийся бюджет. Сетевой отказ не повторяет модель автоматически. Клиент проверяет статус задачи до 280 секунд; 202 означает только запуск, done — сохранённый результат, error — проверенную ошибку. Локальный прямой API сохраняет бюджет 55 секунд. Пропуски A по-прежнему сохраняются без модели. Фоновая задача не раскрывает черновые токены; результат целиком проходит прежнюю проверку.

Если модель пропускает декоративный title, сервер использует фиксированную русскую подпись допустимой категории. Это не добавляет фактов: kind/text/sources и все смысловые проверки сохраняются. Неизвестная категория отклоняется. Причина — воспроизведённый production B с отсутствующими title при содержательном ответе.

Если отсутствует summary, сервер дословно объединяет тексты блоков; он не сочиняет новое резюме. Сами блоки, категории и их источники обязательно проходят каноническую проверку. Лимит ответа увеличен до 5000 токенов; сырой ответ production не журналируется. Дописка — явное возвращение пользователя к ранее пропущенной теме: currentAmendment связывает её с вопросом, currentAnswers связывает текущие ответы с их вопросами и разрешёнными ref.

Промпт 2026-10-03.1: новый словарь тегов с пустым результатом, expectations/userMemory из актуального снимка, ручные правки имеют приоритет. Дополнения о пользователе только из его явных ответов; сервер проверяет sourceId, затем сохраняет memory автоматически и сообщает о новых элементах. Источники не отображаются в настройках. Нельзя восстанавливать отклонённый вывод по прежнему sourceId. A использует правила Сигналов и атомарно обновляет этот отчёт. Изменённые факты во время анализа отклоняют его; новые теги/независимые данные безопасно сливаются со свежим снимком.

Если модель не выделила user-addition, явные собственные предпочтения из A («Я ценю…», «Я хочу…», «Мне важно…») сохраняются дословно из текущего ответа. Это перенос пользовательского утверждения, а не сгенерированная интерпретация. Партнёрские утверждения/догадки не копируются по этому правилу.
