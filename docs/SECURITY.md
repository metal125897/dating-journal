# Доступ и безопасность

По зафиксированному решению MVP без авторизации: любой посетитель с адресом обладает теми же возможностями. URL и noindex не являются защитой. Не добавлять вход самостоятельно и не называть данные приватно защищёнными. Публикация реальных записей возможна только с пониманием этой модели.

DATABASE_URL, GIGACHAT_AUTH_KEY и серверная конфигурация не попадают в браузер, git, логи или чат. `.env.local` исключён, `.env.example` без значений секретов. Ошибки API возвращаются безопасными русскими сообщениями. Для GigaChat корректный CA; TLS verification включён всегда.

Сервер валидирует UUID, enum, даты, размеры текста, команды, версии и согласие. PostgreSQL параметризован. React выводит пользовательский текст как текст, без dangerouslySetInnerHTML. POST только JSON. CORS разрешает лишь точные origin из FRONTEND_ORIGIN (для Pages — https://metal125897.github.io), без wildcard. Запросы без Origin допустимы: это ограничение браузерных запросов, не авторизация посетителей.

Цитата не помещается в URL: ссылка на запись передаёт только ID и числовой диапазон выделения. Серверный CA для GigaChat включён в пакет Functions, не в публичную сборку. Ошибки журналируются только по безопасному классу/коду, без текста запроса, ключей и connection string.

AI сериализован в БД, запросы ограничены частотой и размером. Idempotency не позволяет повторной отправке удваивать записи. Запоздалое основание отклоняется. Источники других людей запрещены. Тексты не используются для обучения приложения; условия внешнего провайдера проверяются отдельно.

Экспорт и полное удаление охватывают все прикладные сущности. После удаления очищаются цитаты, ответы и локальные черновики, согласие сбрасывается. Нельзя обещать удаление ранее отправленного контекста из независимых систем провайдера. Тестировать разрушительные действия только на временном тестовом наборе.
